## Design decision

### Selected: integrated test and evidence harness over accepted subsystem APIs

Add one test-only support module, one integrated test module, a neutral portable-library pilot fixture, and a semantic fresh-context scenario set. Repair the demonstrated exact-navigation adoption gap inside the accepted continuity owner, reference, and focused test. The harness otherwise composes the six accepted owners through their public records/functions. A temporary local clone supplies a real Git repository and existing HEAD without creating a commit; the pilot writes only inside its temporary directory. It exercises source capture through isolated pilot closure and then proves that draft-PR authority is still a separate decision. The selected workspace and ISP-001 remain open and unchanged except for planned evidence/governance files.

This is the smallest coherent design because the deterministic baseline is green apart from the repository-demonstrated navigation-adoption gap. That gap has one clear owner and a narrow compatible behavior. Every other production repair remains conditional on an observed material RED and a recorded bounded implementation amendment.

### Rejected: new package-facing release subsystem

The accepted modules already own every required behavior. A new release controller would duplicate authority, closure, persistence, and review policy and create migration risk without evidence of a missing owner.

### Rejected: speculative edits across accepted modules and references

The current full suite and package/program validators pass. Preemptive hardening would violate the instruction to repair only demonstrated material gaps and would obscure which pressure scenario justified each change.

### Rejected: static-only replacement for the pilot or fresh-context evaluation

Unit and structural checks cannot prove a combined lifecycle or fresh-context model response. Deterministic tests may prepare and validate the scenario catalog, but the five model evaluations remain a distinct synthetic-minimum-context, read-only, externally transmitted evidence step requiring explicit evaluator/egress authority. If that authority or capability is unavailable, INC-008 remains incomplete; static output is not substituted.
