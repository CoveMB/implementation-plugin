- Architecture review: reuse of accepted owners, absence of a second state/closure system, exact interfaces, isolated temporary repository, contextual semantic naming, prompt-policy deduplication, and whether any conditional repair remained owner-local and simpler than alternatives.
- Test-evidence review: genuine RED before repair, focused/full final receipts, interruption coverage, schema fixtures, raw-before-verdict ordering, startup-error handling, no repeated successful unchanged evaluation, and evidence limitations.
- Security/privacy predicate — triggered: fresh external contexts, subprocess arguments, prompt injection, synthetic-minimum-context proof, secret/private-data exclusion, path/symlink containment, output sanitization, and no provider mutation.
- Compatibility predicate — triggered: versioned persisted schemas, current/older/unsupported fixtures, existing public/persisted names, and any repair-envelope activation.
- Reliability predicate — triggered: atomic replacement/fsync contract, append-only writes, injected interruptions, partial evidence, idempotent resume/fail-closed behavior, temporary clone isolation, and unchanged selected workspace.
- Documentation predicate — covered by requirements/architecture: canonical owner links, lean prompt semantics, no copied normative catalogues, and no ISP-001 closure overclaim.
- Reviewer assurance: unless separately authorized dispatch occurs, all reports are actual separate controller self-reviews, non-independent, reduced assurance. No fabricated reviewer or consensus claim.
- Remediation gate: only material findings with concrete evidence, meaningful impact, and benefit exceeding churn may change the frozen candidate. Any repair invalidates affected receipts/reports and requires the smallest focused rerun plus one final coherent suite.

## Commit boundaries

No Git staging or commit will occur. The execution record uses these logical review boundaries only:

1. `integrated-contract-red` — new contracts and preserved failing evidence.
2. `disposable-pilot-green` — deterministic pilot, interruption, and schema behavior.
3. `fresh-context-evidence` — five separately authorized raw outputs and verdicts.
4. `package-naming-readiness` — package/docs/concision/naming and traceability evidence.
5. `reviewed-inc-008-candidate` — final verification, reports, packet, closure-readiness evidence, and handoff.

Each boundary records exact paths and digests. `commit_created` and `staged` remain false. A disposable repository clone reuses existing committed history but creates no new commit.

## Rollback and recovery

- Before each lifecycle write, require expected prior status sequence/digest, expected artifact absence/digest, and fresh repository observation. Use accepted atomic/append-only writers and record per-file receipts.
- Test/pilot state lives in a secure temporary directory. Normal cleanup may remove only that verified temporary directory after required receipts are persisted; injected-failure tests retain evidence long enough to re-open and validate it. Never clean the selected workspace.
- Fresh-context raw outputs are written one file at a time through a temporary sibling plus flush/fsync/replace where supported. A partial result grants no verdict or lifecycle authority. On startup/interruption, preserve the failure receipt and rerun only after a relevant change and renewed preflight.
- If a new file is wrong before it becomes a bound artifact, repair it with `apply_patch`. Once its digest is bound in state/evidence, supersede through a new authorized record; do not silently overwrite history.
- If a conditional repair causes a regression, revert only that clearly attributed unbound repair hunk with `apply_patch`, preserve the RED and recovery evidence, and return to the last validated logical boundary. Never reset, clean, stash, or discard accepted/user work.
- Changed source/program/semantic bindings, head/base/branch drift, conflicts, active Git operation, unsupported evaluator interface, external-data risk, an unplanned file owner, a public/schema/dependency change, or any ISP-001 closure action is a hard stop requiring renewed authority.
- A final unresolved material finding leaves INC-008 unaccepted. The handoff must name the blocker and smallest affected scope; it must not manufacture result files or closure readiness.
